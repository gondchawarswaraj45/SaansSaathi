SECTION A: UNIQUE FEATURES THAT SET US APART
================================================================================

1. "SAANS SCORE" - FAMILY BREATH HEALTH SCORE (HIGH IMPACT)
   
   Concept: A single daily score (0-100) that tells the family how "healthy" 
   their air situation is TODAY, considering both outdoor AQI AND their indoor 
   actions.
   
   Formula:
     SAANS Score = 100 - Outdoor Penalty - Indoor Penalty + Positive Actions
     
     Outdoor Penalty:  Based on AQI category and outdoor time planned
     Indoor Penalty:   Based on indoor pollution sources detected in assessment
     Positive Actions: +5 for air purifier on, +5 for windows closed during bad AQI,
                       +5 for N95 mask worn, +3 for indoor exercise instead of outdoor
   
   Display:
     - Large circular gauge (like a speedometer)
     - Color gradient: red (0) → yellow (50) → green (100)
     - Below gauge: "What's bringing your score down?" (top 3 factors)
     - "What you can do to improve it" (top 3 actions)
   
   Why this works:
     - Gamifies air quality management without being trivial
     - Gives users ONE number to track instead of 6 pollutants
     - Personalizes the experience (family A's score differs from family B's)
     - Makes it easy to see improvement over time

2. "BEST HOUR TO GO OUT" - DAILY WINDOW FINDER
   
   Concept: Show a horizontal timeline bar of today, color-coded by AQI forecast
   or historical pattern. Mark the best 1-2 hour windows for outdoor activities.
   
   Display:
     - 24-hour timeline bar (like a Gantt chart, horizontal)
     - Each hour block colored by predicted/historical AQI
     - Green zones marked with "✅ Best for outdoor"
     - Red zones marked with "🚫 Avoid outdoor"
     - User's planned outdoor activities overlaid on timeline
   
   Data source:
     - Historical AQI patterns from OpenAQ (last 7 days, same hour)
     - Weather context (wind, humidity)
     - Clearly label as "based on historical patterns, not a forecast"

3. "POLLUTION REPORTER" - COMMUNITY FEATURE
   
   Concept: Users can tap to report local pollution events:
     - 🔥 Garbage/biomass burning nearby
     - 🏗️ Construction dust
     - 🏭 Industrial smoke
     - 🚗 Heavy vehicle emissions
   
   Pin shows on the map for 6 hours
   Other users in the area get a notification
   This builds community engagement and crowdsourced data
   
   Technical: reported_incidents table (already in schema)

4. "AIR QUALITY DIARY" - PERSONAL TRACKING
   
   Concept: Users log how they feel each day (1-5 stars for breathing comfort)
   App correlates their diary with AQI data.
   
   After 2 weeks, show:
   "On days when AQI > 200, you rated your comfort 1-2 stars.
    On days when AQI < 100, you rated it 4-5 stars.
    Air quality strongly affects how you feel!"
   
   This creates emotional investment in the data.

5. "INDOOR VS OUTDOOR AQI COMPARISON" - EDUCATION FEATURE
   
   Concept: Show a split card:
     Outdoor AQI: 320 (Very Poor) ← from monitoring station
     Indoor estimated: 180 (Moderate) ← estimated based on windows closed + no indoor sources
   
   Message: "By keeping your windows closed and avoiding indoor smoke sources,
             your indoor air is significantly better than outdoor right now!"
   
   OR: "Your indoor air may be worse than outdoor due to: cooking smoke, incense burning.
        We recommend using the kitchen exhaust and stopping incense while outdoor AQI is High."

SECTION B: CONTENT SUGGESTIONS
================================================================================

EDUCATIONAL ARTICLES TO INCLUDE IN APP:

1. "What is PM2.5 and why should I care?"
   - Explain using relatable analogies (hair strand is 70µm, PM2.5 is 2.5µm)
   - How deep it penetrates (alveoli → bloodstream)
   - WHO and CPCB guidelines
   - Long-term vs short-term effects

2. "10 Free Things You Can Do Right Now to Reduce Indoor Pollution"
   - Damp mopping vs dry sweeping
   - Opening windows at the right time
   - Stopping incense/mosquito coil
   - Using kitchen exhaust
   - Not burning garbage
   - Planting indoor plants (with realistic expectations)

3. "Winter Smog in India: Why November-February is the Worst"
   - Temperature inversion explanation (use diagram)
   - Agricultural burning season
   - Lower wind speeds
   - Vehicle + industrial emissions compounded
   - Interactive map showing season variation

4. "N95 vs Cloth Mask: What Actually Protects You"
   - Based on NCDC and WHO guidance
   - N95/N99 filtering efficiency (95%, 99%)
   - Proper fit testing
   - Cloth mask limitations
   - When to wear (outdoors, AQI > 200)

5. "How to Read the Air Quality Index: A Simple Guide"
   - Indian AQI vs US AQI (they differ!)
   - What each category means
   - What to do at each level (simple language)
   - Infographic format

RECOMMENDED CONTENT APPROACH:
  - Write 3-5 quality articles for MVP
  - Add more gradually
  - Cite all sources (CPCB, WHO, NCDC)
  - Add "Last reviewed" date to articles
  - Review for accuracy before publishing

SECTION C: PERFORMANCE IMPROVEMENTS TO IMPLEMENT
================================================================================

PWA (PROGRESSIVE WEB APP) FEATURES:
  
  1. Service Worker (Add to Vite config):
     - Cache API responses for offline viewing
     - Cache static assets
     - Show "You're offline" banner when network is unavailable
     - Show last-known AQI data when offline
  
  2. Install Prompt:
     - After 2 visits, show "Add SaansSaathi to Home Screen" banner
     - Works on Android Chrome (iOS Safari has limited PWA support)
     - Creates app-like experience without app store submission
  
  3. Push Notifications via Service Worker:
     - Already planned in notification system
     - Service worker required for background push
     - Works even when browser is closed

REACT PERFORMANCE:
  
  1. Use React.memo() for heavy components:
     - AqiTrendChart (Recharts is expensive)
     - MapContainer (Leaflet is expensive)
     - FamilyMemberCard
  
  2. Use useMemo() for calculations:
     - AQI color calculation
     - Recommendation list sorting
     - Family risk level calculation
  
  3. Use useCallback() for event handlers:
     - API call functions passed to child components
     - Map event handlers

  4. Virtual scrolling for long lists:
     - Notifications list (can be long)
     - Use react-virtual or @tanstack/react-virtual
  
  5. Debounce location search:
     - Add 300ms debounce on city search input
     - Prevents API call on every keystroke

SECTION D: ACCESSIBILITY & INCLUSION SUGGESTIONS
================================================================================

MULTILINGUAL SUPPORT (Phase 2):
  
  Priority languages for Indian users:
  1. English (default)
  2. Hindi (हिन्दी)
  3. Marathi (मराठी) - for Pune/Mumbai users
  
  Implementation:
  - Use react-i18next library
  - Create /src/i18n/ folder with en.json, hi.json, mr.json
  - Store language preference in user_preferences table
  - Language toggle in settings page
  
  Key strings to translate:
  - AQI category names
  - Health advisory messages
  - Navigation labels
  - Form labels
  - Alert messages

LOW-BANDWIDTH MODE:
  Many Indian users have limited data plans.
  
  Options:
  - "Lite Mode" toggle in settings
  - In lite mode: No animated charts (show static values instead)
  - In lite mode: No map page (show station list instead)
  - In lite mode: Smaller image assets
  - In lite mode: Reduced API polling (60 min instead of 15 min)

SCREEN READER SUPPORT:
  - Add aria-label to all icon buttons ("Close modal", "Search location")
  - Add aria-live="polite" to AQI value display (announce changes)
  - Use semantic HTML elements (nav, main, section, article)
  - Add skip-to-main-content link at top of page
  - Test with NVDA (free screen reader for Windows)

WHAT CAN FAIL YOUR DEMO:
  ❌ API returning no data (OpenAQ may not cover your demo city)
     → Pre-load sample data for a few cities as fallback
     → Choose Delhi/Mumbai for demo (best OpenAQ coverage)
  
  ❌ Render backend cold start during demo (30-60 seconds wait)
     → Start your demo by opening the backend URL first
     → Keep a browser tab open to /api/health to prevent sleep
  
  ❌ Gemini API rate limit hit during demo
     → Prepare a backup response cache
     → Avoid live demos with multiple people testing simultaneously
  
  ❌ Map not loading (browser extension blocking)
     → Test in incognito mode before demo
     → Disable ad blockers for demo
  
  ❌ Stale JWT token on demo day
     → Log in fresh at the start of demo
     → Clear localStorage before demo
